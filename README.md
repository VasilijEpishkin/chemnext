# ChemNEXT — подготовка структур для молекулярного моделирования

Два Python CLI-инструмента из тестового задания по вычислительной химии. Они **подготавливают входные данные** для GROMACS и AutoDock Vina, но **не запускают молекулярную динамику или докинг**. Для воспроизводимой проверки включены небольшие тесты на известных молекулах.

## Установка

Рекомендуется Conda: часть OpenFF-зависимостей, прежде всего AmberTools, не всегда устанавливается через pip.

```bash
conda env create -f environment.yml
conda activate chemnext
```

Альтернативная установка через `python -m venv .venv` и `pip install -r requirements.txt` возможна только если все зависимости доступны в выбранной системе. Файл `environment.yml` — основной воспроизводимый способ установки.

## Задание 1. Параметризация малых молекул для GROMACS

На вход подаётся SDF с готовыми 3D-конформерами. RDKit читает структуры, OpenFF Sage назначает параметры, Interchange записывает `.gro` и `.top` **для каждого успешно обработанного лиганда**.

```bash
python task1/convert_to_gromacs.py --input input/example.sdf --output output/task1
python task1/convert_to_gromacs.py -i input/example.sdf -o output/task1 -n 2 -v
```

| Опция | Назначение |
|---|---|
| `-i, --input` | SDF с молекулами, обязательный |
| `-o, --output` | Папка результатов, по умолчанию `output/ligands` |
| `-ff, --forcefield` | Силовое поле, по умолчанию `openff-2.2.0.offxml` |
| `-n, --limit` | Обработать первые N молекул |
| `--no-coord-check` | Отключить проверку координат (для диагностики, не рекомендовано) |
| `--log-file`, `-v, --verbose` | Лог и подробный вывод |

Проверка по умолчанию сравнивает **исходные координаты RDKit и OpenFF в ангстремах** с порогом 0,001 Å по каждой координате. При несовпадении, отсутствующих либо неконечных координатах молекула отклоняется, а не просто отмечается предупреждением. После экспорта проверяются наличие файлов, число атомов, конечность координат и параметры коробки в `.gro`. Это контроль целостности экспорта, **не доказательство физической корректности силового поля**.

Результаты — `output/task1/<имя молекулы>/topol.gro` и `topol.top`. Если хотя бы одна молекула завершилась ошибкой, скрипт записывает её в лог и возвращает ненулевой код выхода; при этом результаты успешно обработанных молекул сохраняются.

## Задание 2. Подготовка лигандов для AutoDock Vina

Принимает `.smi`/`.smiles` или `.sdf` (также директорию с такими файлами); генерирует 3D-конформер ETKDGv3, оптимизирует MMFF94 и готовит PDBQT с помощью Meeko.

```bash
python task2/convert_to_pdbqt.py --input input/example.smi --output output/task2
python task2/convert_to_pdbqt.py --input input/example.sdf --output output/task2
python task2/convert_to_pdbqt.py --input input/ --output output/task2
```

| Опция | Назначение |
|---|---|
| `-i, --input` | SMILES/SDF либо папка, обязательный |
| `-o, --output` | Папка с PDBQT |
| `-f, --flex-rings` | Разрешить обработку гибких циклов при подготовке Meeko |
| `--min-ring-size` | Минимальный размер обрабатываемого цикла, по умолчанию 6 |
| `--log-file`, `-v, --verbose` | Лог и подробный вывод |

Скрипт проверяет наличие параметров MMFF94, успешность генерации конформера (ETKDGv3), сходимость оптимизации (до 500 итераций), конечность атомных координат и рассчитанной энергии MMFF94. После экспорта проверяется, что PDBQT содержит атомные записи с конечными координатами. Если хотя бы одна молекула не прошла проверки, команда возвращает ненулевой код выхода. Результаты корректно обработанных молекул остаются в папке.

**Научные ограничения:** ETKDGv3 создаёт один конформер с фиксированным seed=42, а не исчерпывающий конформационный ансамбль. MMFF94 не поддерживает всю химию (например, некоторые металлоорганические соединения), поэтому неподдерживаемые молекулы отклоняются, а не оптимизируются другим силовым полем без уведомления. PDBQT не сохраняет всю химическую информацию исходных SDF/SMILES; успешная подготовка PDBQT ещё не означает валидный docking pose. Для проверки качества докинга нужен конкретный рецептор и экспериментальная или эталонная поза (redocking).

## Тесты и воспроизводимость

```bash
conda activate chemnext
python -m pytest -q
```

`tests/test_scientific_validation.py` проверяет на этаноле и бензоле: генерацию и оптимизацию конформеров, конечность MMFF-энергии, разумные длины связей для **этих конкретных тестовых соединений**, PDBQT, контроль координат при переходе RDKit → OpenFF, структуру файлов `.gro/.top` и диагностические ветки отказа. При отсутствии OpenFF/Meeko соответствующие тесты **пропускаются** — это не успешное прохождение химического расчёта. Запускайте их в полном Conda-окружении.

При установленном GROMACS (`gmx` в PATH) `tests/test_gromacs_energy.py` дополнительно компилирует созданные для этанола `.gro/.top` через `gmx grompp`, выполняет короткую минимизацию и проверяет конечность значений Potential в `.edr`. Конфигурация: `validation/minimization.mdp`. Без GROMACS этот тест пропускается.

```bash
# Ручной запуск GROMACS для уже подготовленного и проверенного лиганда
gmx grompp -f validation/minimization.mdp \
  -c output/task1/ethanol/topol.gro \
  -p output/task1/ethanol/topol.top \
  -o output/task1/ethanol/minimization.tpr
gmx mdrun -s output/task1/ethanol/minimization.tpr \
  -deffnm output/task1/ethanol/minimization -nt 1
```

Это только минимальный **sanity-check топологии и конечности энергии в вакуумной коробке**; он не подтверждает биофизическую релевантность параметризации или правильность молекулярной динамики в растворителе. Полная валидация потребует отдельного протокола, эталонов, проверки стереохимии, протонирования, зарядов и результатов dock/MD.

## Структура

```text
task1/       # чтение SDF, параметризация OpenFF, экспорт GROMACS
task2/       # чтение SMILES/SDF, ETKDGv3, MMFF, Meeko, PDBQT
tests/       # химические и (опционально) GROMACS smoke-тесты
validation/  # минимальный GROMACS .mdp для проверки энергии
input/       # пример входных молекул
```

Код демонстрирует инженерную подготовку научных данных, проверку ошибок и ограничений метода; проект изначально выполнен как тестовое задание.
